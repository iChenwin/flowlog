# FlowLog Native 0.2 架构与兼容边界

本文按 `native/` 当前实现复审，记录日期为 2026 年 10 月 21 日。它描述已经实现的机制及其边界，不代表已经完整复现 Logseq，也不将自动测试通过等同于长期数据安全认证。

## 1. Windows 界面与编辑器

入口为 `native/Program.cs`，运行环境是 Windows 的 .NET Framework 4.8，界面使用 WPF。`MainWindow.cs` 直接创建 WPF 窗口、布局、按钮、滚动区和文件夹选择器。原生版本的运行路径不加载 React 页面，不启动本地网页服务，不创建 Electron、WebView 或 WebView2 控件。WPF 是 Windows 的托管桌面界面框架；这里的“原生”不表示应用使用 C++ 编写或已经编译成不依赖 .NET 的机器码。

`Editor.cs` 的 `OutlineEditor` 继承 AvalonEdit 6.3.1.120 的 `TextEditor`。每篇笔记使用一个连续的 `TextDocument`，由 AvalonEdit 提供文本选择、剪贴板、光标和撤销栈。块操作修改该文档中的字符范围，而不是给每个块创建独立输入框。页面导航保留编辑器实例，保留该实例的选择和撤销历史。

`Outline.cs` 在原始文本上计算行偏移、缩进、块和子树范围。当前块语法为以空格或 Tab 缩进后接 `- ` 的行；一个 Tab 按两格处理。它识别反引号和波浪线围栏代码区，避免对代码行套用部分大纲快捷键。呈现层将块标记绘制为圆点、隐藏非活动元数据行、着色任务及链接；原文模式显示 Markdown。切换呈现模式不重写文档。

已实现的编辑动作包括块拆分和块内换行、缩进和反缩进、键盘移动子树、同一编辑器内拖动块、块起始位置合并、折叠、任务状态切换、页面链接补全、有限斜杠命令、生成块 ID 并复制引用。这些操作使用分组撤销，并记录相关选择和折叠状态。任务快捷键主要循环 `TODO → DOING → DONE → 普通块`。它仍是基于文本及规则的大纲编辑器，没有实现 Logseq 的完整图数据库、语法解析器或全部块语义。

输入法组合期间有避免拦截确认键的处理，但代码和合成输入测试无法替代不同中文输入法、候选窗、触屏及辅助功能的实际验收。图片、PDF、白板、公式、嵌入式查询、插件和复杂富文本没有在本版实现完整呈现能力。

## 2. 流式日记与保存调度

`MainWindow.cs` 在一个滚动区按日期倒序加入每日笔记，每批加入七篇，接近底部时继续追加已有日记。今天的空日记先作为内存对象出现，开始编辑后再保存。当前实现使用 `StackPanel`，不是能够回收已离屏编辑器的完整虚拟化列表；持续向下展开会累计编辑器和文档内存。

搜索、任务汇总和反向链接基于启动时载入的笔记及内存中的待保存内容扫描。反向链接主要匹配 `[[页面名]]`，不是 DataScript/Datalog 查询。块引用通过查找 `id::` 属性定位。没有文件系统监听器，外部修改不会即时更新所有搜索结果和已打开视图；保存时的版本校验承担主要冲突检测职责，用户可以明确选择重新读取。

编辑后先持久化恢复草稿，再用约 350 毫秒的防抖调度后台保存。每篇笔记维护待保存文本、正在保存状态及磁盘版本。保存期间的新输入保留在待保存状态，旧快照成功后再处理新版本。窗口关闭时等待正常保存完成；有保存失败或冲突时保留窗口，提供导出草稿及确认后放弃修改、重新读取的入口。

## 3. 文件、编码和页面命名

`Storage.cs` 的 `VaultStore` 管理用户选定的普通文件夹，核心数据始终是本地 Markdown 文件，没有云端服务或强制数据库迁移。默认目录为系统“文档”目录下的 `FlowLog`。最近使用的库路径单独保存在 `%APPDATA%/FlowLogNative/last-vault.txt`，与旧网页版本的设置机制分开。

| 对象 | 当前规则 |
| --- | --- |
| 每日日记 | `journals/YYYY_MM_DD.md`；内部日期为 `yyyy-MM-dd` |
| 新建页面 | `pages/<UTF-8 百分编码标题>.md` |
| 标题恢复 | 文件名去掉扩展名后执行 `Uri.UnescapeDataString` |
| Windows 保留设备名 | 如 `CON`，新建时将首字符编码，避免设备名冲突 |
| 标题末尾的点 | 逐个编码为 `%2E`，保留 `tail.` 与 `tail` 的区别 |
| 扫描范围 | 仅 `journals`、`pages` 的直接子文件，不递归扫描目录 |

中文、斜杠、emoji、末尾点及类似 `..` 的标题通过编码进入单个文件名；解码出的斜杠只是标题字符，不作为路径重新拼接。路径校验仅允许这两个目录下的 Markdown 文件，拒绝绝对路径、额外目录层级、非法 Windows 文件名字符及其他扩展名。已有笔记库目录和文件的祖先路径会检查 reparse point，拒绝符号链接及 junction。

读取使用严格 UTF-8。UTF-8 BOM 会从编辑文本中分离记录，保存既有文件时保留其 BOM 状态；新文件默认无 BOM。UTF-16、GBK 或非法 UTF-8 不会被自动猜测转换，读取会报错，原文件保持不动。一篇无法解码的文件目前会使整次笔记库读取失败，尚无逐篇隔离的修复界面。

CRLF、LF 及原有文本在存储层按原文传递，不会为了“大纲化”给普通段落统一加 `- `。未改动不触发正常编辑保存，存储层收到相同字节时也不替换文件或新增备份。新增块采用文档已有的 CRLF，否则使用 LF；混合行尾、单独 CR 的特殊文档经过具体编辑动作后，不承诺所有新增行维持原分布。

这不是 Logseq 文件格式的完整兼容实现。它不解释 `config.edn` 的自定义日记格式，不递归处理页面目录，不按 `title::` 或别名属性重建页面标题，不实现 Logseq 的命名空间、所有历史文件名转换规则或 Org-mode 支持。已有文件名中的合法百分转义会被解码，不能假定包含字面 `%20` 的旧文件一定按原字面标题展示。Windows 文件名大小写碰撞、路径及单文件名长度限制依然适用；百分编码会明显增长中文标题对应的文件名。它也不是 Logseq 数据库版本的数据库读取器。

## 4. 版本、冲突和备份

每篇笔记的 `Revision` 是磁盘原始字节的 SHA-256，包含 BOM 和行尾差异；文件不存在时版本为空。保存带入编辑所基于的 `expectedRevision`，第一次读取磁盘后进行比较。不同则拒绝覆盖，在 `.flowlog/conflicts` 下分别写出磁盘内容和本地待写入内容；若磁盘文件已删除，只能保存本地副本。

实际替换前会在 `.flowlog/backups/<相对路径 SHA-256>/` 写入旧内容，每篇保留最近二十份。备份以时间、随机片段及截短的可读文件名命名，内容是原始文件字节。冲突副本也使用受限长度名称，避免把百分编码后的长标题反复拼进路径。没有自动清理冲突副本的策略，目录可能持续增长。

备份完成后、正式替换前，再读取一次磁盘字节并核对版本，发现期间有变化则同样保留冲突副本并停止替换。正常写入在同一目录创建随机临时文件，写入后调用 `Flush(true)`，已有文件使用 Windows `File.Replace`，新文件使用 `File.Move`。每个库同时使用进程内锁与当前 Windows 会话内的命名 Mutex，串行化遵守本协议的 FlowLog 存储操作。

两次校验之间及最后一次校验与 `File.Replace` 之间仍有时间差。第三方编辑器不受 FlowLog Mutex 约束，仍可能在最后检查后修改或替换文件。当前实现不能提供针对任意外部程序的原子“版本相同才替换”保证，也不能宣称完全消除 TOCTOU 竞争。reparse point 检查同样是路径层面的检查，不是基于已打开目录句柄的完整抗路径交换方案。

`Flush(true)` 和同目录替换提升了正常本地文件系统上的保存可靠性，但没有给断电、磁盘故障、网络共享、同步软件、杀毒软件介入或文件系统驱动行为作绝对保证。备份保存在同一笔记库，不是异机灾难恢复。应用内尚无备份浏览和逐版恢复界面。

## 5. 恢复草稿

恢复草稿保存在 `%APPDATA%/FlowLogNative/drafts/<笔记库路径哈希>/`，与原笔记文件分开。每篇 XML 保存完整相对路径、标题、日期、日记标志、BOM 状态、基础磁盘版本及 Base64 编码的完整 UTF-8 文本，因此未创建 Markdown 文件的新笔记也能恢复。

读取草稿时重新比较磁盘版本。若磁盘字节已经等于草稿的完整编码内容，说明可能是保存成功后、清理草稿前退出，返回实际磁盘版本并避免误报冲突。其余版本不一致的草稿明确标为冲突，界面不自动覆盖磁盘。保存完成后的草稿会正常清除；放弃尚未保存的修改需要用户明确确认。

草稿不是无限历史，也没有加密。每个库、每条路径只有一个草稿文件。`Program.Main` 在应用整个运行期间持有按用户 SID 命名的 `Local` Mutex，在当前 Windows 会话内限制同一用户运行一个 FlowLog 实例；第二实例提示使用已有窗口并退出。异常结束后的 abandoned mutex 允许下一次启动接管。这防止正常启动路径下两个窗口争用同一草稿文件；它没有实现窗口间草稿所有权协议，也不保证跨 Windows 会话并发或绕过程序入口直接调用存储 API 的隔离。库目录移动后对应的路径哈希变化，不会自动搜索或搬迁旧草稿。

## 6. 与 Logseq 实现的区别及来源

Logseq 官方公开代码说明其编辑器以 ClojureScript、React/Rum 和 DataScript 等组件构建，并列出 Electron 桌面代码目录；官方 `package.json` 也包含 Electron 入口及构建脚本。Logseq 的流式编辑体验本身不能作为“它使用 Windows 原生控件”的证据。参见 [官方代码结构说明](https://github.com/logseq/logseq/blob/master/CODEBASE_OVERVIEW.md)、[官方构建入口](https://github.com/logseq/logseq/blob/master/package.json) 以及更贴近文件型笔记库的 [Logseq OG 代码结构说明](https://github.com/logseq/og/blob/version/file/CODEBASE_OVERVIEW.md)。这些仓库分支会继续变化，不能把一个分支的说明当成所有 Logseq 版本的完整架构。

FlowLog Native 从这些可观察的使用行为出发，使用 C#、WPF、AvalonEdit 和普通 Markdown 文件独立实现范围有限的 Windows 编辑器。它没有把 Logseq 的 ClojureScript 编辑器转译或移植为 C#，没有复制其 AGPL 源文件，也没有声称复用了其完整编辑内核。该区别意味着交互与兼容性仍需逐项验证，不能用“照抄 Logseq”替代验收结果。

Logseq 官方仓库提供 [AGPL-3.0 许可证原文](https://github.com/logseq/logseq/blob/master/LICENSE.md)。FlowLog 仓库中的自有代码使用仓库现有 MIT 许可证；原生编辑器依赖 AvalonEdit 的 MIT 版本，随包保留 `native/THIRD-PARTY-NOTICES.txt`。若未来引入 Logseq 源码或其他依赖，需要单独审查并履行对应许可证，不能由本说明推导出任意复制源代码的授权。

## 7. 验证范围和仍需完成的长期验证

`StorageTests.cs` 使用自行创建的临时笔记库验证字节保存、BOM/CRLF、相同内容不写入、备份、版本冲突、草稿恢复、已保存草稿识别、路径及扩展名限制、特殊标题和长编码文件名。`EditorTests.cs` 检查文档编辑与撤销等行为，`MainWindowTests.cs` 检查实际 WPF 窗口、导航、连续加载日记、关闭保存、重开恢复和外部编辑冲突。测试不使用用户真实笔记库。存储测试已在 .NET Framework 可执行文件中运行，而不只是在现代 PowerShell 的 .NET 运行时加载测试库；两者的旧路径限制不同。

已有测试没有覆盖数周真实使用、数万篇笔记的内存和延迟、多用户会话并发、所有保存阶段的强杀或断电、磁盘写满及权限变化、XML 草稿损坏、系统还原、网络盘及同步工具竞争、文件系统攻击压力测试、所有 Logseq 历史库格式，以及不同输入法和屏幕阅读器的完整组合。现有测试和手动截图能够证明其中一组具体场景的结果，不能证明这些未覆盖场景已经安全或达到 Logseq 的完整体验。
